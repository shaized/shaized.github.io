ENGINEERING NOTES / THIS WEBSITE

Small surface.
Clear boundaries.

Security is a set of design decisions and verification habits. Here are the choices behind this public website, and what they do—and do not—provide.

01 / ARCHITECTURE

A static, public notebook.

GitHub Pages serves HTML, CSS, JavaScript, images, and fonts. There are no sign-in flows, custom backend services, payment forms, or private API keys in this site. Every shipped asset is public.

This reduces application complexity. It does not remove risks from hosting, repository access, browser behavior, or future content changes.

02 / DATA BOUNDARY

Public data stays public.

The news desk reads a bundled CISA KEV snapshot and attempts a fresh copy from CISA’s official GitHub mirror. It validates the structure and shows the catalog date. If the request fails, the dated snapshot remains available.

Searches and checklist inputs are processed in your browser. They are not submitted to a server. Theme and reading preferences use local browser storage.

Read the privacy notice ↗
03 / BROWSER SAFEGUARDS

Keep the sources narrow.

A Content Security Policy limits scripts, styles, fonts, images, and media to this site. Network requests are limited to this site and the official data mirror. Scripts are separate files; feed values are rendered as text, not executable HTML.

The policy is delivered in HTML. GitHub Pages controls HTTP headers, so this site does not claim complete control over server-level protections.

04 / AI & EVIDENCE

Examples, without implied access.

Agent walkthroughs are handcrafted fictional examples. They do not invoke AI models, query an organization, or perform response actions. Conceptual visuals do not depict an actual workplace.

In operational systems, tool permissions, source provenance, human review, and outcome verification require their own implementation and testing.

Read the editorial policy ↗
05 / ACCESSIBILITY

Motion is a choice.

Pause animations using the control in the header or the accessibility panel. System reduced-motion preferences take priority. The site also offers light and dark themes, larger text, higher contrast, link underlining, and text spacing.

Keyboard and responsive checks support the design. They are not a substitute for a comprehensive assistive-technology audit.

06 / REPORTING

Found something to improve?

For an accessibility problem, broken link, or suspected security issue, email Shai with the affected page and a concise description. Please avoid including credentials, personal records, or sensitive operational data.
